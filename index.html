02 / GENERALIZATION

四类泛化，看模型改变了什么

固定训练集，分别统计四类成功率。以下案例说明测试方式，不代表已完成的实验。

01

动作任务泛化

完成训练中未见过的任务或技能组合。

测试案例

训练：开抽屉、抓取分别学过。
测试：开抽屉 → 把物体放进去。

PLUS
不直接覆盖；扰动组合 ≠ 新技能组合。
PRO
部分覆盖：task 目标变化，不等于新技能。
VLABench
Track 5 跨任务；需自行锁定训练／留出任务。
02

语言泛化

理解同义表达，并随目标指令改变动作。

测试案例 · 场景固定

同义：“拿杯子” ↔ “把杯子拿起来”。
换目标：“拿杯子” → “拿碗”。

PLUS
指令改写：同一目标的不同表达。
PRO
language 改写 + task 目标切换。
VLABench
Track 3／4：常识线索、上下文语义。
03

视觉泛化

指令不变，场景或目标实例变化后仍能执行。

测试案例 · 始终“拿杯子”

换位置：杯子从左侧移到右侧。
换实例：换成未见过的形状／颜色。

PLUS
目标移位、物体布局与干扰物。
PRO
位置交换、物体替换与外观变化。
VLABench
Track 2：未见类别与实例。
04

无关扰动鲁棒性

目标和任务不变，抵抗无关环境变化。

测试案例 · 始终“拿杯子”

杯子与位置不变。
只换桌面纹理、光照或图像噪声。

PLUS
背景、光照、噪声、相机变化。
PRO
环境变化；按官方可用配置与初态选取。
VLABench
Track 6：未见背景与桌面纹理。

分类原则 换杯子实例 → 视觉；指令从杯子换成碗 → 语言。颜色若用于指定目标，就不是无关扰动。

“未见”以实际训练集为准；同场景反事实需核对初态与成功条件。覆盖依据：PLUS · PRO · VLABench。

03 / MECHANISM ANALYSIS

信息关注 → 信息编码 → 信息使用

同一场景、同一指令「拿红杯子」：从看哪里，到有什么，再到是否真用。

C · 图像 / 语言M · 动作
01 / 信息关注

动作在看哪里？

分析什么
是否关注红杯子，以及指令中的“红”“杯子”。
怎么实现
读取动作 query 对图像区域和指令词的 attention，画成热图。
02 / 信息编码

动作表示里有什么？

分析什么
动作 hidden 能否读出“红色”和“杯子”。
怎么实现
冻结模型，用等容量线性探针读取各层 C / M；比较留出样本准确率。
03 / 信息使用

这些信息决定动作吗？

分析什么
内部换成“蓝杯子”，动作是否随之转向蓝杯子。
怎么实现
输入不变，逐层换入配对“拿蓝杯子”的表示；对比随机替换，再验证执行目标。

证据边界 关注 ≠ 编码 ≠ 使用。三项共用配对场景与语义标签；图中均为示意，因果判断还需干预对照与执行验证。
